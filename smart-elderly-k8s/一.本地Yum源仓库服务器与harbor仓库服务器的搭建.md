##### 1.什么是本地Yum源仓库？

```properties
Yum源仓库=repo安装源=dnf源仓库 >>>都是指软件包仓库，一个存放RPM包和元数据的目录，让包管理器**(yum,dnf)**知道去哪里下载，安装，更新软件。

repository 仓库 ----  在软件领域里就是一个集中存放东西的地方，dnf/yum里存放的是RPM包+元数据； Git里，存的是代码 ； Docker里，存的是镜像,这时候就是镜像仓库服务器里的一个具体项目/文件夹，同一个项目下可以有多个版本。

registry 仓库服务(一个服务器) ----用来存放和分发镜像，仓库运行在仓库服务上

他们的配置文件一样：/etc/yum.repos.d/
元数据一样： 都有repodata/repomd.xml 这个总索引文件（他的下面文件记录着包的详细信息）

元数据：描述数据的数据，记录数据的位置和其他内容，等于就是索引，告诉你想找的文件内容在哪，在repo里面这就是描述仓库中有哪些包以及位置。所以元数据等于就是dnf的地图，我们dnf下载时先找到仓库地址，再去下载总索引文件，根据总索引文件找到其他元数据文件，**所以我们在新加入rpm包时，一定要重新更新元数据 createrepo --update**


```

##### 3.自定义Yum仓库

```shell
#安装nginx,用它提供的http服务作为Yum仓库的访问入口

dnf install -y nginx

systemctl enable nginx --now

dnf install -y createrepo 

#createrepo是用于生成yum仓库元数据的工具，从而让dnf/yum能识别包

mkdir -p /var/localrepo

createrepo --update /var/localrepo/

#加杠表示这是个目录，更加直白，生成的repodata就在这个目录下
-----------------------------------------------------------------------

#配置yum仓库，将软件包添加到自定义的localrepo里面
[root@repo ~]# ls
anaconda-ks.cfg  docker
[root@repo ~]# dnf install rsync -y
[root@repo ~]# rsync -av docker/ /var/localrepo/docker/
#-a 归档模式，作用是尽可能完整地保留源文件地属性，rsync会自动创建最后一个目录不存在的话
[root@repo ~]# createrepo --update /var/localrepo/
#更新元数据

-----------------------------------------------------------------------
#修改nginx配置，让页面能访问localrepo仓库
cat > /etc/nginx/conf.d/localrepo.conf <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name 192.168.88.100;

    location /localrepo/ {
        alias /var/localrepo/;
        autoindex on;
        autoindex_exact_size off;
        autoindex_localtime on;
    }
}
EOF

nginx -t
nginx -s reload
访问192.168.88.100/localrepo
```

```properties
为什么要让web服务器能看到仓库目录呢？

首先nginx提供了一个web服务，让别人通过http可以浏览到文件，底层就是当其他机器上配置了`baseurl=http://192.168.88.100/localrepo/` 时，`dnf` 会去请求这个 URL。然后就会去请求元数据进行下载软件包。

如果只在自己机器上使用其实是没有必要的。

访问网页就能下载，是因为 HTTP 响应的本质就是“把文件字节流发回去”。浏览器看到 Content-Type 不是它能渲染的类型，就触发下载。 Nginx 只是把本地文件原样通过 HTTP 吐出来，浏览器和 dnf 都能拿。就是说你在浏览器里面点这个链接也会直接下载，dnf访问到这个链接也会下载
```

##### 4.部署harbor仓库

harbor仓库服务器的信息：

| 主机名 | IP地址         | 规格    | 角色         |
| ------ | -------------- | ------- | ------------ |
| harbor | 192.168.88.101 | 2CPU 2G | 私有镜像仓库 |

基础配置操作同上          

======================================================================

```shell
1.#首先安装docker部署来部署harbor仓库

dnf install -y docker-ce docker-compose-plugin

systemctl enable docker --now

docker --version

#配置路由转发，是让harbor容器内部能够通信，因为它是多个容器组成，他们走的是docker内部网络需要ip_forward 转发。还有容器与宿主机的转发

echo 'net.ipv4.ip_forward = 1' >> /etc/sysctl.conf

sysctl -p

#将harbor-offline-installer-v2.15.2.tgz解压，得到harbor目录/usr/local/harbor

tar -xvf harbor-offline-installer-v2.15.2.tgz

cd harbor && docker load -i harbor.v2.15.2.tar.gz

```

```shell
2.#创建https证书，还是在harbor目录下---- 自建CA证书签发机构

mkdir tls

openssl genrsa -out tls/ca.key 4096

#生成私钥文件到tls/ca.key

openssl req -new -x509 -days 3650 -key tls/ca.key -out tls/cert.crt

#生成一个根证书用刚才的ca.key签名，输出证书公钥文件cert.crt(公钥+签名信息)

======================================================================创建harbor证书

 openssl genrsa -out tls/harbor.key 4096

openssl req -new -key tls/harbor.key -out tls/harbor.csr

#同上，生成私钥，从而生成证书，用CA私钥签名得到证书文件

======================================================================

创建SAN配置文件

cat > harbor-ext.cnf <<'EOF'

authorityKeyIdentifier=keyid,issuer

basicConstraints=CA:FALSE

keyUsage=digitalSignature,keyEncipherment

extendedKeyUsage=serverAuth

subjectAltName=@alt_names

[alt_names]

DNS.1=harbor

IP.1=192.168.88.101 

EOF

======================================================================用CA给harbor签发证书

 openssl x509 -req \

-in tls/harbor.csr \

 -CA tls/cert.crt \

-CAkey tls/ca.key \

  -CAcreateserial \

 -out tls/harbor.crt \

-days 3650 \

-sha256 \

  -extfile harbor-ext.cnf

======================================================================ls tls/ #得到六个证书数量

openssl x509 -in tls/harbor.crt -noout -text
```

harbor服务端先生成一个私钥，再根据这个私钥生成CSR（证书签名请求），里面包含自身的IP域名，服务端公钥，然后将这些打包给CA（证书签发机构，他有一套密钥，用私钥签名），输出一个证书文件（Harbor 公钥、域名 / IP、CA 的签名、有效期）。将证书挂载到nginx,443端口开启TLS（Transport Layer Security，传输层安全协议）。ssl是老版本

客户端访问harbor仓库时，发起连接（携带支持的TLS版本），服务端返回服务端证书，客户端校验证书（CA公钥IP），确定是该服务器，建立连接生成对称密钥，后续http用这个密钥加密传输

SAN 是 X.509 证书的扩展字段，用于在一张证书中绑定多个身份标识（域名、IP 地址）。

